# Phase 0 (preflight) review

Independent review of commit `cbc5670` on `claude/festive-babbage-7yhhx8`, measured against the phase 0 acceptance
criteria and the engineering standards. The preflight script was not run. Checks that were run locally, with no network
and only fake values: `tsc -p scripts/tsconfig.json` (passes); `pg_dump --version` (16.15); Node 22.22 `fetch`/`URL`
error messages; libpq's parse errors for a malformed URI.

Checked with no finding: every file is under 400 lines (largest 119) and every function is under 60 lines (largest
about 22). Strict TypeScript passes with no `any`. Every probe id matches an id in `config/setup-items.json`. No
committed file contains a credential-shaped string. Apart from row 12, every remote call is a read (GET, or the read-only
POST methods of UptimeRobot and Lightsail), and the psql survey runs inside `begin transaction read only`.

## Resolution (23 Oct 2026, before phase 1 continued)

| Finding | Resolution |
| --- | --- |
| blocker: psql stderr could quote the connection string; URI in argv | `probes-db.ts` parses the URL in Node, passes credentials through `PG*` variables (PGPASSWORD), never argv; psql output is mapped to fixed categories and never echoed |
| URLs and error messages copied into reports | `safeUrl()` keeps origin and path only; `errorCode()` returns a code, never a message |
| mailbox and intake key "verified" on presence | now `unfilled`: "present, not exercised"; `ran` names the actual source |
| connector rows overriding fresh results; `validated_at` reset each run | merge rules rewritten: fresh verified or refused wins; a refused run plus verified connector evidence shows both; connector rows dated by `run_at`; evidence older than 7 days becomes `unfilled` |
| `pg_dump` 16 against server 17 | the database probe compares majors; D-022 records that a pg_dump 17 client is installed before the dump |
| refused rows without a fix | `Row` is a discriminated union: `fix` is required when `status = refused`; all refused paths now carry one; the merge file is rejected if a refused row lacks one |
| `meta` had no probe; staging/advisors not re-exercised | `probeMeta` added (Graph `act_<id>`); staging and advisors stay connector evidence, dated and ageing out after 7 days, and PHASES.md says so |
| B2B key "referrals-only" verified with all scopes | item retitled; an annotation records the scope query and the replacement fix (D-017) |
| follow-up calls without status checks | every follow-up reports "could not read X (HTTP n)" and never yields a fix |
| `hostOf` throwing; `Promise.all` aborting | `hostOf` returns a placeholder; every probe runs in `guarded()`, a crash becomes a refused row |
| survey errors blamed on the connection string | connect check and survey separated, each attributed to its own row |
| B2B probe writes usage counters | documented (D-021); CHANGES.md corrected |
| literals in source | phone prefix (psql variable), referral code, Lightsail host template read from `defaults.json` |
| `model_keys` unused | the database probe emits an `ai_key` row from it |
| connector rows unvalidated | ids, statuses and `run_at` validated; the run fails on an unknown value |
| `stores` paths vs seeded keys | settings paths aligned; `chatwoot` and `whatsapp` settings keys seeded; duplicate alert block removed |
| D-016 listed AWS as verified | corrected |
| unrecorded evidence | Lightsail regions, Vercel deploy branch and B2B scopes recorded as annotations with what was run |
| stale `website_health` row; `PROD_DB_URL` | row removed (the script verifies it); wording corrected |
| D-002 without the owner's words | D-002 now quotes the instruction and where it was given |
